# V2 可行性方案对抗性辩论纪要与裁决

> 两轮辩论：codex 任反方全力攻击 V2，我方（V2 作者）第二轮区分接受与反驳并抛出新发现。
> 本文是裁决，不是任何一方的陈词。裁决人保留对双方的否定权，且对法规事实做了独立核验。

## 0. 裁决摘要

**V2 的业务重构方向成立，但论证质量不合格，且存在一处足以推翻上线路径的致命遗漏。**

| 维度 | 裁决 |
|---|---|
| V2 的业务锚定（漫剧短剧、tvmao、网文改编、6+1） | **成立**，是相对 V1 的真进步 |
| V2 的 R1–R10 论证 | **不合格**：4 条实质失实、3 条过度概括、3 条部分成立 |
| V2 的成本模型 | **不足**：缺可用率 U、缺收入侧、四本账混淆 |
| V2 的治理时序（M3 制度化） | **驳回**：阈值可后校准，测量定义不能后置 |
| V2 遗漏的微短剧行业准入 | **致命**，且 V1 同样遗漏 |
| 直接进入 M2 整剧（80 集） | **No-Go**，改为分批 Gate |
| M0 首集样片 | **Conditional Go**，条件见 §4 |

**最重要的单条结论**：AI 微短剧有**专属的、比普通微短剧更低的**监管划档门槛，且相关制度在过去 30 天内刚刚变更两次。V1 与 V2 都建立在对此完全无知的基础上。

## 1. 我方认输的 12 项（codex 打中，已核对确认）

按杀伤力排序：

| # | 指控 | 核对结论 |
|---|---|---|
| 1 | **测量定义不能推迟到 M3** | 成立且最有力。V1 §16.1 明确把 Minimal Eval Runner、隐藏数据隔离、不可变 Bundle 哈希、只读 Champion 指针列为 P0；V2 以"阈值需真实基线校准"为由推到 M3，实际删掉了 V1 的最低证据门槛。**自指陷阱真实存在**：M0–M2 若 Rubric、验收者、严重度分类不冻结，攒出的"基线"不可横比，无法用于 M3 校准 |
| 2 | **配音顺序断裂** | 成立。V2 §4.1 写"图→视频→配音合成"，§4.4 又要求生成前存在 `dialogue_audio_ref`，§5.4 说 duration_gate 依赖配音时长。V2 的流程无法满足自己的合同 |

## 2. codex 让步的 3 项（第二轮撤回或降级）

| # | 原判 | 修订后 | 裁决人意见 |
|---|---|---|---|
| 1 | R2/R5/R6 = `STRAWMAN` | 降为"部分属实 + 过度概括" | **接受修订**。codex 给出的判据合理：稻草人是"命题被替换且攻击依赖该替换"，过度概括是"原命题真实存在，仅结论强度过头"。V2 完整引用了 V1 的限定条件并保留其正确部分，属后者。但 V2 的"V1 主张"转述仍须改写 |
| 2 | 总成本 15–80 万（含 Owner 工时） | 改为四本账分列 | **接受**。对单人公司，决策相关量是现金断点。四本账：`production_cash_cost` / `go_to_market_cash` / `economic_resource_cost` / `declared_regulatory_investment`。第四本账是本次辩论的重要产物（见 §3） |
| 3 | 必须 8+1 或 10+1 席 | 6+1 条件性成立 | **接受，但采纳其改进映射**。成立前提是"职责重新映射 + 外部批处理 + 事件聚合"，不是单纯把调用脚本化 |

codex 的席位重映射优于 V2 原方案，采纳：

| 席 | 职责 |
|---|---|
| 1 | 制片统筹 |
| 2 | 选题、权利研究、市场与发行策略 |
| 3 | 编剧 |
| 4 | 导演、分镜、表演 |
| 5 | 视觉美术与资产连续性 |
| 6 | **声音、后期与交付** |
| 7 | 独立 QA |

关键变化：**生成执行不再占据独立席位**，改为「视觉/导演席发布生成计划 → 受管批处理队列执行 tvmao → 事件聚合器按批汇总 → 相关专业席处理异常与验收」。这直接落实了 V1 §5.8"Agent 只处理计划、例外和验收"的要求。V2 原方案把生成+后期+声音三条专业链压进一席才是真正的瓶颈来源。

同时采纳 codex 的前置容量门禁（替代 V2「连续 2 个复盘周期」的模糊触发）：`p95 message_queue_age > 4h` 连续 3 个生产日、turn 利用率持续 >65%、周计划缺口 >20%、单一专业占阻断缺陷 >35%——满足任一即临时拆席。

## 3. 裁决人对 codex 的事实纠正（双方均未掌握的最新法规）

codex 第二轮称"2026 年新办法仍是征求意见稿，应以现行分类通知为基础"。**此判断已过时**，裁决人独立核验结果如下：

### 3.1 《微短剧发展管理办法》已正式公布

〔外部事实，2026-08-02 核验〕该办法已经 **2026-07-27 国家广电总局局务会审议通过**，2026-07-31 公布，**自 2026-09-01 起施行**——即本文日期起 30 天后生效。codex 引用的 2026-06-24 征求意见稿已被正式文本取代。

要点：

- **定义**：单集时长少于 20 分钟，主题主线明确、故事情节连续完整、人物角色突出的剧集；
- **三类分档**：一类（投资额度较大或特殊题材）／二类（投资额度相对不大且一般题材）／三类（投资额度较低且一般题材）；具体门槛由主管部门另行制定并适时调整；
- **第三十四条**：使用人工智能技术生成、制作的微短剧，制作机构和播出单位应当遵守国家有关规定，并**依据有关规定在每集明显位置添加提示标识**；
- **审核**：一类、二类微短剧在播出前应向省级以上广电主管部门申请内容审核和发行许可，审核期限 20 日；三类由播出单位播前审核并标注节目编号；
- **平台责任**：核验一、二类许可证，对三类审核并在线报备，建立内容安全全流程责任追溯机制，**不得使用诱导用户沉迷、过度消费的算法模型**。

### 3.2 AI 微短剧有专属划档标准，且门槛更低

〔外部事实〕国家广电总局网络视听司《管理提示（AI 微短剧分类分层标准）》**已于 2026-07-01 实施**（本文日期前一个月）：

| 档位 | AI 微短剧门槛 | 对比：普通微短剧门槛 |
|---|---|---|
| 重点 | **投资 ≥80 万**，或特殊题材 | 投资 ≥100 万，或特殊题材，或平台招商主推／首页首屏推荐 |
| 普通 | 30 万（含）–80 万，一般题材 | 30 万–100 万，且非重点推荐 |
| 其他 | <30 万，一般题材 | <30 万，且非重点推荐 |

**裁决**：监管对 AI 微短剧的重点档门槛设得比普通微短剧**更低（80 万 vs 100 万）**。这直接推翻了"AI 生产方式天然享有合规红利"的乐观读法——低成本确实可能落入轻审核路径，但 AI 身份本身收窄了这条通道，且要求每集标识。

特殊题材范围（触发重点档，与投资额无关）：政治、军事、外交、国家安全、统战、民族、宗教、司法、公安。

### 3.3 我方原推断的修正

| 我方第二轮主张 | 裁决 |
|---|---|
| "规划备案在开拍前" | **成立**。官方流程为「账号申请→规划备案→拍摄制作→上线备案→播出」，明确"获得规划备案号后即可拍摄" |
| "成片后不能补办，永久失去主推资格" | **驳回（采纳 codex 反驳）**。总局通知明确可视情采用"规划备案等材料后补"支持新业态；且拟首页首屏首推的完成片由总局复核，本身即为完成片进入更高路径留有机制。正确表述：升档存在**审核周期与商业窗口风险**，而非法律上的绝对不可逆 |
| "首页主推是唯一规模化流量来源" | **驳回**。缺乏依据。还存在普通算法推荐、付费投流、搜索流量、剧场推荐、平台精品扶持等路径 |
| "低成本是制度红利" | **降级为条件性判断**。监管"总投资"口径含剧本、制作、后期、**宣发**，不等于视频 API 账单。制作费 20 万 + 宣发 15 万即可能跨过 30 万线。且不得通过把宣发、IP、关联方服务移出账面来规避划档 |

### 3.4 主体资质（codex 的高价值发现，裁决人确认）

- 〔事实〕《网络剧片发行许可证》是针对**具体完成作品**的发行许可，**不是**公司长期持有的机构资质——V2 §9.2 的表述有误；
- 〔事实〕机构层面的核心资质是**《广播电视节目制作经营许可证》**；
- 〔事实〕申请该证需独立法人资格，且需提交**不少于三名主要管理人员**的专业材料；
- 〔推断〕**纯单人主体无法自行取得**该资质。走重点/普通档只有两条路：自建满足人员条件的法人实体，或与持证制作机构**实质联合出品**（非挂靠——持证方须作为第一出品或申报主体并承担真实审核责任）；
- 〔推断〕若走联合出品，分账、第一出品署名、IP 归属、平台后台数据访问权、备案送审控制权、下架合规责任、续集与真人化衍生权全部需要重新谈判——**这改变商业模式本身，不只是增加一道流程**。

## 4. 最终裁决与修订指令

### 4.1 门禁判定

| 阶段 | 裁决 |
|---|---|
| **D0 发行与监管路径选择** | **必须新增，且位于 IP 采购之前** |
| M0 首集样片 | **Conditional Go**——条件：D0 完成 + 测量治理就位 + 音频前置 |
| M1 前三集 | Conditional Go |
| M2 直接 80 集整剧 | **No-Go**——改为 8–12 集小批次 + 分批 Gate |
| V2 的"中高可行"结论 | **下调**为：技术中高、运营中、商业未知、发行合规未闭合 |

### 4.2 D0 决策清单（第 0 号决策，开拍前完成）

1. 目标平台与发行主体；
2. 初始监管档位及依据（按 AI 微短剧标准：≥80 万或特殊题材→重点）；
3. 是否自愿按重点申报以保留平台资源可能；
4. 申报主体与《广播电视节目制作经营许可证》状态（自建 vs 联合出品）；
5. 规划备案、成片审查、平台审核的周期估算；
6. **按监管口径（含宣发）的总投资预算**——这是划档依据，与制作现金成本不是同一本账；
7. 从其他档升级为重点档时，平台与主管部门接受的补充/变更路径；
8. 升档失败时的发行降级方案；
9. **2026-09-01 新办法生效后的政策再验证节点**。

### 4.3 必须提前到 M0 的治理组件（驳回 V2 的 M3 推迟）

1. 稳定 ID、不可变生成事件与失败事件日志；
2. Skill/Prompt/Profile/模型/参考资产完整 manifest；
3. **冻结的缺陷分类、严重度与验收 Rubric 版本**；
4. 验收者、时间、判定与修改理由记录；
5. 原始／开发／隐藏评测数据的物理隔离；
6. 最小无状态 Eval Runner（脚本 + 隔离临时目录即可）；
7. 只读 Champion 指针与手工回滚流程；
8. QA 只读生产记录、不可改成本源数据；
9. 权利、配音同意、平台审核与 GateDecision 的不可变记录；
10. **失败、取消、被过滤、只采用部分片段也必须进入成本台账**（否则算不出真实 U）。

原则：**阈值可以在 M3 校准，但测量定义不能在 M3 才出现。**

### 4.5 仍待实测或书面确认的开放项

1. 不同镜头复杂度的 `A`、`U`、`R_eff` 分布（M0 首个观测，M1 三集后形成分层基线）；
2. 监管"总投资"对 Owner 自有劳动、IP 分成、实物投入、平台补贴、后置投流的计入口径；
3. 目标属地是否接受已完成"其他"档剧补做规划备案，及变更周期；
4. 抖音/红果对招商主推、首页首屏、普通推荐、付费投流的档位执行口径；
5. 周更 N 下 6+1 的 p95 队列时延与最大稳定吞吐；
6. 自有公司能否满足制作经营许可证的人员与场所条件，或必须引入持证联合出品方；
7. 2026-09-01 新办法生效后，配套细则对 30/80 万划档的最终影响；
8. 巨量/红果后台是否开放随机分配、逐曝光日志、排除原因与 SRM 所需数据（决定 §8.4 投流层实验能否成立）。

## 5. 需要 Owner 回答的 6 个问题

1. **第一部剧通过哪个持证/备案主体上线？**自建法人取证，还是与持证制作方联合出品？（若联合出品，接受怎样的分账与控制权让渡？）
2. **按监管口径的总投资预算控制在哪一档？**<30 万走"其他"档轻审核，还是主动按重点档申报以保留平台资源可能？
3. **周更 N 是多少？首发集数与安全库存要求？**
4. **IP 合同的最低保底、分成、独家窗口、审看轮数与反馈 SLA？**
5. **平台收入分成、投流归因窗口与现金止损线？**
6. **目标 TTS/配音方案能否在视频生成前产出稳定、可商用、可引用的定时音轨？**（这决定 M0 能否开工）
